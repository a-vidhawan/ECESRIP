## Training / Testing Datasets

| Dataset | Format | Size | Neurons | Patterns | How Generated |
|---|---|---|---|---|---|
| Random bipolar (small demo) | NumPy array, ±1 | N patterns × N dims | 8 | 3 | `random_patterns(N=8, P=3, seed=42)` in `hopfield_train.py` |
| Random bipolar (medium) | NumPy array, ±1 | N patterns × N dims | 16 | 4 | `random_patterns(N=16, P=4, seed=42)` |
| Pattern file (custom) | `.txt`, one row per pattern, space-sep ±1 | Variable | Variable | Variable | Hand-specified or from application data |
| sklearn Digits (8×8 MNIST-like) | Binarised, ±1 | 5 patterns × 64 dims | 64 | 5 (digits 0–4) | `mnist_demo.py` (this meeting) |

**Note on "testing" data:** Hopfield networks don't use a held-out test set in the supervised-learning sense. Testing = corrupting stored patterns (1–n bit flips) and measuring recall accuracy + overlap.

**Standard evaluation protocol:**
1. Store P patterns in W.
2. For each pattern, generate a noisy probe (k random bit flips).
3. Run async/sync updates until convergence.
4. Check if recovered state matches the original (overlap = 1.0 = perfect recall).
5. Sweep k from 1 to N/2 to find the basin of attraction radius.

## Capacity & Scaling Reference

| N (neurons) | Max patterns (Hebbian) | Truth table rows | Q-M feasible? | Demo in repo? |
|---|---|---|---|---|
| 8 | ~1 | 256 | ✅ < 1s | ✅ Default demo |
| 10 | ~1 | 1,024 | ✅ < 1s | — |
| 12 | ~2 | 4,096 | ✅ < 5s | — |
| 16 | ~2 | 65,536 | ✅ ~seconds | — |
| 20 | ~3 | ~1 M | ⚠️ Minutes | — |
| 64 | ~9 | 1.8×10¹⁹ | ❌ Not feasible | MNIST demo only |
| 256 | ~35 | Astronomical | ❌ | — |

**Key constraint:** The truth-table enumeration step is only feasible for N ≤ 20. For N > 20, alternative hardware mapping strategies are needed (BDD-based, direct arithmetic threshold comparator).
